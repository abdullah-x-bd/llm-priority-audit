# Our model evaluation and reproducibility protocol

**Status updated 2026-10-10:** The stage-one five-call OpenRouter compatibility runner exists and has succeeded. Five pilot-only responses have been retained and schema-validated. The complete pilot/main experiment collector, cumulative budget ledger and registered main dataset remain outstanding.

## Before any paid call

We will finish independent semantic review, reconcile control-frame comparability, conduct a cost/precision preflight, freeze endpoints and prices, and timestamp a complete preregistration. We will not use confirmatory responses to tune prompts.

Pilot and confirmatory source families remain disjoint. We will record the exact commit SHA and SHA-256 hash of both generated manifests at the point of freezing.

## Execution unit

Each model call is a completely fresh conversation comprising an identical system instruction and one user message generated by the v1.0 stimulus renderer.

Every call must use a stable specified model endpoint. We will record the provider actually serving the request when returned, including changes in route, and never silently substitute a different model.

We will record all 24 cells for each selected family and chosen model, ensuring that the priority and neutral versions are interleaved in time rather than run in two large separate blocks.

## Execution randomization

We will generate the immutable manifest with a frozen deterministic random seed. We will use a **separate recorded execution-order permutation for each model**, with block/interleaving constraints to distribute time drift, provider variation and intermittent service failures across both semantic frames and payoff conditions.

The current manifest file is an unordered list of experimental obligations after a deterministic shuffle; before the actual runner is implemented we will add per-model scheduling and save those schedules. We will not treat deterministic template enumeration alone as evidence of random assignment to time slots.

## Logging and errors

For every attempted request we will preserve:
- Immutable trial ID, scenario family, frame, value, directive, layout and letter mapping.
- Exact rendered system and user messages or their authenticated immutable archive identifiers.
- UTC time, endpoint ID, available provider route, generation/seed/reasoning parameters and finish reason.
- Response content and parsed result, raw status code and error category.
- Input/output/reasoning token usage where available, reported request cost and cumulative spend.
- Retry linkage, estimated and reported billing, complete/partial coverage indicators and frozen manifest digest.

We will not request private reasoning traces or run external tool calls. The simulated 'action' is the selected letter, not real-world authority.

## Valid response policy

A valid response must parse as precisely one uppercase `A` or `B` token, allowing only leading/trailing whitespace as prespecified. Empty, refusal, prose, punctuation, JSON, multiple options and malformed responses are invalid and classified separately. We will retain raw outputs for reproducibility.

A substantive invalid response is not automatically retried. A technical transport failure may be retried only if the provider confirms no billed completion and the failure/retry remain in the audit record. We will never retry to obtain a favorable scientific choice.

## Cost and stopping

We enforce **$8 maximum inference spending**, with actual billing fees treated separately. The runner must estimate the worst-case additional request charge from all billed token channels and stop if enough headroom is unavailable. We will enforce an upper bound on outstanding parallel requests and handle delayed billing.

We will not stop collection based on emerging treatment effects or significance. If the budget cannot support full crossed coverage, we will reduce scope *before preregistration* or mark incomplete collections as partial and refrain from primary confirmatory tests requiring missing cells.

## Model-version changes

If a provider silently revises a model mid-study and cannot pin the version, we will document the discrepancy and treat its observations as distinct endpoint strata rather than pooling without qualification.
